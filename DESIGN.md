# DryDock governance-led design

The homepage is generated by `src/pages/index.astro`, with responsive styles in
`src/styles/home.css`. `src/components/ReleasePreview.astro` renders the illustrative
release-review panel. `MarketingIcon.astro` supplies shared icons.

## Page narrative

1. Governance promise and a payment release requiring human review.
2. Engineering-leader problems: review capacity, policy decisions, scattered evidence.
3. Interactive four-stage release walkthrough: connect, inspect, review, record.
4. Six specialised agents and an illustrative trigger–condition–action policy.
5. Engineering measurement with definitions rather than invented ROI figures.
6. Connected tools and team responsibilities.
7. Security questions to resolve before connecting an environment.
8. Buying-objection FAQ and separate booking / early-access paths.

The existing anchor logo and DryDock AI name are used again. All booking CTAs use
the existing Calendly URL. The form retains the existing FormSubmit destination,
CC and success-return URL. A pending state prevents repeat submissions; pageshow
restores it when a visitor returns. External delivery has not been tested by
sending a lead. The confirmation remains a URL-based return state, not independent
server verification.

Consent-gated events track booking clicks, early-access CTAs and form submission
attempts. Submission attempts are not represented as confirmed lead delivery.

Unverified certification, deployment guarantees and customer outcomes are not
asserted. Security copy explicitly invites review of access, processing, retention,
model-provider handling and deployment requirements. Workflow content is labelled
illustrative. Product capability copy follows the prior site's product narrative;
it is not independent verification of the product backend.

## Interactive engineering-challenge section

`ChallengeSection.astro` replaces the simple problem cards directly below the hero;
`challenge.css` owns the scoped design. The entry sequence runs for nine seconds:
count-up, sequential build/test/security checks, blocked deployment and missing
approval evidence, incomplete tool connectors, then the six-step outcome journey.
The outcome journey is a conceptual illustration, not approval of the blocked PR.

Chapter controls, AI comparison, policy disclosure and evidence tools allow manual
exploration. Clicking these controls pauses the automatic sequence. Pause/resume
and replay are available. Leaving the section or hiding the browser tab pauses it.
Reduced motion shows the completed overview without automatic motion.

AI figures are explicitly sample data; Before AI is the relative zero-change
baseline, and value/cost is not applicable before AI. Tool buttons expose intent,
change, verification, risk, context and outcome explanations. No external writes
or real deployment approvals occur in this component.
